# Result-window presentation seam

`DiagramWindow::setPresentation(heading, context, warning)` supplies a short window heading, optional run/scope context and an optional concise interpretation warning. Diagrams have no expandable technical-detail panels. The warning wraps above the capped, top-aligned context without a fixed height limit, so long identifiers cannot clip it. Callers document calculation details in the user guide. The chart's axes, samples, time formatting and export provider are unchanged. The window never guesses from chart titles: callers set chart/window titles explicitly. Authored IDs may contain `|`, so delimiter-based title parsing is unsafe. `setRollingStockSubject(true)` hides the train filter and train selection controls and uses input-traction-specific navigation help. The existing `inputTrainUnitId` property switches this on when callers set their chart. Do not enable train filtering on an input rolling-stock curve. `TimetableTableWindow::setPresentation` accepts a concise heading and case/scenario context; `setRunProvenance` supplies those identities without changing CSV/PNG provenance.

The result windows cap their initial width/height to 90%/80% of the available screen and retain their chart/table navigation and export controls. The table still shows all nine columns with horizontal scrolling where needed. Disabled buttons and read-only fields inherit the existing stylesheet; no new data-dependent states are introduced.

The input traction, route, blocking-time and compressed blocking-time callers provide explicit scope and essential interpretation warnings. Run Results groups diagram actions in a menu and keeps exports and baseline actions separate. Capacity results retain complete scope and method notes alongside the pair, compression and critical-block tables. Incident delay comparison separates the metric heading from baseline and incident-run identities. Both custom result dialogs use `DialogLayout` for a screen-bounded scrollable body and fixed Close footer. CSV export and the compressed-chart action remain in the body rather than widening the footer. The creator acceptance path checks their bounded geometry, enlarged-font and long-context behavior, and table contents.

Inspector fields remain read-only. Signal member details use a light, wrapped text panel; long field values remain available through selection and tooltips. Editor docks use scrollable outer viewports to prevent their forms from enlarging the main window. Compact numeric fields show full precision during editing and preserve the stored value when an untouched field gains or loses focus.
