Feature status 2026-10-17¶

This page records what was checked in EGTRAIN on one day, and what the check found. It is a dated snapshot, like the release rehearsal of 2026-10-17. It is not a specification and it is not kept up to date. Later changes are not reflected here.

Snapshot¶

Item

Value

Date

2026-10-17

Commit

c59b0314 on main (“Correct the messages for opening and importing cases”, #888)

Version shown by About EGTRAIN

1.0.0

Platforms

macOS 26.6.2 on Apple silicon, Windows 11 (an Arm64 virtual machine that runs the x64 build by emulation), Linux (Ubuntu 24.04)

The test names in the tables are the tests that ctest -N lists at this commit in a configuration with tests on. The pull request checks of #888 passed on Linux, macOS and Windows. The last Release workflow run, 39019990227, ran on 950b145c, four commits earlier, and all its validation and package jobs passed. That run also executed the smokes that the pull request checks leave out: headless_smoke.py on all six scenes, the editor, scene render, track preview and visual polish smokes, and the round trip, bundle, assignment and incident smokes. The tests were not run again for this page.

How to read the tables¶

Verdict

Meaning

tested

The feature works as intended. A test named in the evidence covers it, or a manual run named in the evidence used it.

untested

No test and no manual run covers it. It may work.

partial

It works only in part. The evidence says which part.

placeholder

The control exists and does nothing useful.

unreachable

The code exists and a user of the shipped application cannot get to it.

A cell that starts with a test name is a CTest test. Some tests are registered on some platforms only: the Bash smokes are not registered on Windows, and the visual polish smokes run on macOS only. The platform coverage table lists them.

Limitations and deferred¶

  • The Windows evidence comes from an Arm64 virtual machine that emulates x64. The update to version 1.0.2 failed there on the candidates of this page; a later candidate installed it (see Checks after this snapshot). Timings and drawing speed on that machine do not stand for a physical PC.

  • The Linux evidence for the packaged application is the automated rehearsal under a virtual display and a start of the AppImage by hand in a container (see Checks after this snapshot); the manual Linux runs of the editors and results used a build from source in a container. Nobody has used the AppImage on a Linux desktop with a graphics card.

  • No scene has signals. Every committed case has one network-wide signalling area at level 0, so signal-based separation is not exercised by any of them.

  • A case saved by this version cannot be upgraded from an older schema, because there is no older schema. The upgrade flow is code that the shipped application cannot reach.

  • The replay keeps every frame of a run (#460). The scrolling of the canvas, the trackpad and the wheel cannot be proved from tool output, also not on a physical Mac, where the test tool reaches only the accessible controls and the canvas has none; a person has to check them. test_networkview and the visual polish smoke cover them in code.

  • The macOS and Windows packages of the release candidates were not signed in the runs that were rehearsed. A signed and notarized build has not been rehearsed (#402 and #404 are closed; the rehearsals used runs that skip signing).

  • Applying a downloaded update on a Windows installed copy is not supported; the release page is the way (#405).

  • The source-backed Assignment case is deferred until the OpenTrack data are available (#181, #182, #228).

  • Undo and recovery have limits: the application keeps the newest 20 recovery copies and warns about a copy whose original changed, is newer or is missing (see Checks after this snapshot).
