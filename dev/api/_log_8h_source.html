9// Categorised console output without Qt. A message has a category and a level. The rules given
10// to configure() switch each pair on or off, and the sink receives the text of every enabled
11// message. EG_LOG writes one message as a stream expression:
12//
13// EG_LOG(SimSetup, Warning) << "Train " << name << " has no route\n";
14//
15// The text reaches the sink as streamed: the caller writes the newline.

63// Sets the enabled pairs: the defaults, then the rules in order, and the later rule wins.
64// The rules use the syntax of QT_LOGGING_RULES, limited to this grammar:
65// - Rules are separated by ';' or a newline. Blanks (space, tab, carriage return) around a
66// rule, a name and a value are ignored. An empty rule is skipped.
67// - A rule is split at its first '=' and is `pattern=true` or `pattern=false`, in lower case.
68// - A pattern is a name pattern with an optional level suffix `.debug`, `.info`, `.warning`
69// or `.error`. The suffix is the text after the last '.' when it is a level name. Without
70// a suffix the rule applies to all four levels.
71// - A name pattern is `*`, a category name, or a name with a '*' at the start, at the end or
72// at both ends: `sim.*`, `*.run`, `*step*`. A '*' anywhere else is malformed.
73// - A pattern that matches no category is well formed and changes nothing.
74// A malformed rule is skipped and the others still apply. Returns false when any rule is
75// malformed. configure("") restores the defaults.
76bool configure(const std::string& rules);
77
78// Calls configure() with the value of the environment variable EGTRAIN_LOG, or with an empty

82// Flushes std::cout and std::cerr, which the default sink and the sink of the application write
