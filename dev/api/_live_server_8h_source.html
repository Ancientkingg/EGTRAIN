13// The transport of the live contract: a ZeroMQ PUB socket that publishes frames to any number of
14// subscribers on this machine and, when commands are enabled, a REP socket that takes run-control
15// requests. Both sockets listen on 127.0.0.1 only. A server that is not started holds no thread,
16// no context and no socket. No Qt.
17//
18// The server carries frame text that the caller has made (see io/LiveFrame.h) and neither reads
19// nor changes it. A published frame is two parts: a topic, then the text.
20//
21// One I/O thread, started by start(), creates, uses and closes every ZeroMQ socket, because a
22// socket must not be shared between threads. Every other thread uses the push functions and
23// tryPopCommand. They take a mutex for a few instructions and never wait for the I/O thread, a
24// socket or a subscriber, so a step of the simulation cannot stall on the transport.
25//
26// Frames wait in bounded queues until the I/O thread sends them, in the order in which they were
27// pushed. When the state queue is full, the oldest waiting state frame is dropped: a subscriber
28// misses it, and sees the gap in the seq of the frames. Hello and event frames are never dropped; a
29// push that finds their queue full is refused. A subscriber that does not read loses frames at its
30// own high-water mark, without effect on the others.
31//
32// start and stop are called from one thread at a time. The other functions can be called from any
33// thread.
34
35// The first part of a published frame.
