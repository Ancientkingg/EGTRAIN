Detailed Description

The state that one simulation run builds up and that the next run must not see.

The routines of the simulation library take the run that they work on as a parameter, and the member functions of a train reach it through Train::run_, which the operations builder sets.

The process has one run, defaultRun(). It has a fixed address, so reset() clears every member in place. The window reads the run through DispatchController::run(), which gives the same run; a test that calls the builders itself passes it defaultRun() or a run of its own. DispatchController::prepareScene clears it with reset(), builds a run apart from it and puts the finished run in its place with adopt(). A scene with errors leaves it cleared, the infrastructure included. DispatchController::runSimulation then steps the run on the thread of the run and adds the results, which stay until the next scene is prepared. A member that is added here must be cleared in reset(), or in resetInfrastructure() when it belongs to the infrastructure, and a member that points at another member needs a line in adopt().

Besides the run, the simulation uses this process-wide state: initial_variables (the options, which the operations builder reads and writes and prepareScene copies into settings), the controller simulation, SimulationWorker::active(), and the constants timestep (1 s), signalCode1 to signalCode3 and the array sizes kMaxTrackLines, kMaxConnections and kMaxStations of Infrastructure.h.

Member Function Documentation

◆ adopt()

void SimulationRun::adopt ( SimulationRun && staged)

Replaces every member by that of a run that the builders have filled. The lists and vectors move, so their elements stay where they are and the pointers between the elements stay valid. The trains are pointed at this run and the indexes are built again for the lists of this run. The staged run is left without contents and is not used again.
