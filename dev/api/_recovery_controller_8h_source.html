29// Writes a recovery copy of a scene while the scene has unsaved edits, through a RecoveryStore.
30//
31// The first edit after a write arms a single-shot timer. When it fires, the newest scene is
32// written, unless that revision is already on disk. Later edits do not move the timer, so a copy is
33// never more than one interval behind the editing. The interval is 30 seconds, or the value in
34// QEGTRAIN_RECOVERY_INTERVAL_MS when that is a positive whole number of milliseconds.
35//
36// The write runs on one worker thread, because saving a bundle takes tens of milliseconds for the
37// largest committed scene and longer when the disk or a virus scanner is slow. One job runs at a
38// time. Edits that arrive while a job runs are merged: when it ends, the newest scene is written
39// once. The scene handed over is never modified, so the editing thread needs no lock.
40//
41// Saving, replacing the scene and returning to the clean state each bump an epoch and remove the
42// copy. A write that is under way cannot be stopped, but its result is dropped and the removal runs
43// after it, so a late write never brings back a copy that a save removed. A write that has not
44// started when the epoch changes does not run.
45//
46// A failure is reported with writeFailed and never stops the editing: nothing here blocks the
47// caller except scan, adopt, discard and shutdown, which wait for a job that is running. No
48// function throws, prints or logs.
49//
50// All functions belong to the thread that owns the object, which runs the event loop. Signals are
51// emitted there. The controller holds the store alone: the store is used by one thread at a time
52// and has no static state.
