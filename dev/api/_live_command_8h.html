Detailed Description

The requests that a client sends to the command socket of the live stream (see io/LiveServer.h) and the checks that decide whether the server accepts one. The functions read text and touch no socket, thread or run, so any thread can call them. No Qt. The requests, replies and reasons are described under Requests in docs/architecture/external-sharing.md.

The commands are the ones that change the timing of a run or end it: they never change the railway, and a run that receives only pause, resume and set_delay_ms gives the same results as one that receives nothing.

Enumeration Type Documentation

◆ LiveCommandKind

enum class LiveCommandKind
strong

What a client can ask of a run. The server queues the request and the simulation applies it at the top of a step.

Enumerator
Pause 

"pause": the run waits at the top of a step until a resume or a stop.

Resume 

"resume": ends a pause; without a pause it changes nothing.

Stop 

"stop": ends the run as cancelled, before its next step.

SetDelayMs 

"set_delay_ms": sets the wait at the top of each step to LiveCommand::delayMs.

◆ parseLiveRequest()

LiveRequest parseLiveRequest ( std::string_view text,
const std::string & token )

Checks the text of a request. It has to be at most kLiveMaxRequestBytes long, a JSON object with the contract version, an id of at most kLiveMaxRequestIdBytes, the token and the name of a command. The first check that fails gives the reason: too_large, bad_json, bad_version, bad_argument, bad_token, unknown_command. set_delay_ms also needs args.delay_ms, a whole number from 0 to kLiveMaxDelayMs, or the reason is bad_argument. The token is compared in a time that depends on its length only.
