Detailed Description

Sends usage and diagnostic events to the compiled receiver from a worker thread of its own. Producers on any thread hand events to an in-memory ring of 128 entries without waiting. Once a second the worker re-reads consent through its own TelemetryConsent, stores events in a TelemetryQueue and posts batches over HTTPS, handling each response as the HTTP outcomes of docs/telemetry/README.md say. Only the process that owns the queue sends; in others every event is dropped. A sender whose context is not capable, or whose construction fails, starts no thread and accepts nothing. The worker exits by itself once it can send nothing more in this run: after a receiver change, a 410 response, or a failed consent read or storage operation.

◆ invalidateConsent()

void telemetry::TelemetrySender::invalidateConsent ( bool usage,
bool diagnostics )
noexcept

Refuses the named categories at once and invalidates tokens taken before. The worker's next pump drops every waiting event, not only those of the named categories, and purges the queued events of the named categories. They open again at the first consent read after that pump that finds them enabled while no revocation is pending. Connected directly to TelemetryConsent::revoked. Never waits.
